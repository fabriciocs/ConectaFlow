## Changes made in this pass

- Added versioned event, job and result schemas under
  `docs/contracts/wa-akg/v1/`.
- Added deterministic inbound event identity and negative/unit coverage in
  `src/lib/inbound-event-identity.ts` and its tests.
- Added runtime validation for the versioned inbound envelope and aligned the
  event/result JSON schemas with the emitted identifiers and evidence fields.
  Webhook fan-out now follows the owner/SUPERADMIN session authorization policy
  instead of using the legacy shared-access relation.
- Added an additive `InboundEvent` receipt model, claim/requeue transitions and
  a reviewed-but-not-applied migration. The WhatsApp store records the receipt
  before media download/message persistence; the webhook reuses that receipt,
  links the persisted `Message` and media reference, emits a versioned envelope
  before fan-out and skips duplicate receipts.
- Prepared an isolated `C:\repos\n8n-local\audio-worker` scaffold with a
  token-protected `/transcribe` endpoint, 50 MiB limit, mandatory event/job/
  correlation identifiers and `wa-akg.result.v1` output. Dependencies,
  readiness and a direct real-media E2E request are verified; operational
  classification remains partial until the n8n path and worker-token injection
  are verified.
- Corrected the maintenance scripts to resolve their root from `$PSScriptRoot`
  instead of the stale `C:\n8n-local` path. The scripts were not executed.
- Created the inactive n8n draft `X7xQjxoAN1krFfnF` in the personal project:
  `Receive Audio Contract (Draft)` → `Normalize WA-AKG Audio Envelope` →
  `Call Local Audio Worker` → `Persist Processing Result`. It carries
  `eventId`, `jobId`, `correlationId`, `subjectId`, `sessionId`, model and
  language as multipart fields, reads the worker token only from the
  `AUDIO_WORKER_TOKEN` environment variable, and sends the result to the
  signed/token-protected WA-AKG ingestion route using
  `WA_AKG_RESULT_WEBHOOK_TOKEN`.
  It was validated and saved inactive; it was not published or activated.
- Added durable `ProcessingResult` persistence keyed by `(eventId, jobId)`,
  signed internal result ingestion at
  `POST /api/internal/processing-results`, and authorized textual search at
  `GET /api/processing-results/{sessionId}`. The route enforces the inbound
  event job, correlation, subject and public-session scope before linking the
  result and advancing the inbound status.
- Added bounded recovery of expired `InboundEvent` processing leases. A
  crashed worker can now move expired `PROCESSING` receipts back to `QUEUED`
  conditionally, preserving replay without allowing two recoverers to claim
  the same lease.
- Added authorized job status at `GET /api/processing-jobs/{jobId}`. The
  route authenticates through the existing session/API-key/OAuth policy,
  checks ownership or SUPERADMIN access against the event's database session,
  and returns status, attempts, timestamps, modality, original message id and
  the persisted result. The view deliberately omits raw event data, claim
  tokens, payload hashes, internal message ids and the raw media path.
- Added pure projection coverage for the job status response: 2/2 focused
  tests passed, including current-envelope and legacy-payload redaction.

F2 remains `IMPLEMENTED/PENDING_MIGRATION/RUNTIME_UNVERIFIED`: the code and
isolated SQL are present, but the current dirty release has five older
migrations pending and there is no validated backup/restore window, so the new
migration was not applied. Real MySQL concurrency, replay and lease recovery
still require an isolated integration environment.

## Security and operational blockers

- The n8n Compose stack contains a privileged DinD runner and lacks explicit
  resource limits; this remains a documented P1 risk.
- SearXNG uses `latest` and lacks a healthcheck in Compose.
- The existing active raw-event workflow contains a media API header value in
  its saved node parameters. It was not copied into this report; treat it as
  compromised and rotate it before publishing any workflow change.
- Two active ingestion workflows use different transcription destinations;
  choose one worker contract before enabling E2E processing.

  worker is currently listening on `127.0.0.1:8765`.
- `GET /health` returned HTTP 200 with authentication configured; Caddy
  `/powershell/health` also returned HTTP 200.

  without the required processing context returned HTTP 400.

  not the n8n path.

  draft with a controlled WAV pin. n8n returned `access to env vars denied`
  before the HTTP call, confirming that `$env` is blocked by the current n8n
  policy. The draft and worker were restored afterward; the auxiliary worker
  on port `8766` is stopped. Native n8n credentials are required for the next
  authenticated E2E attempt, and the global environment block must remain on.
- The MCP package was rechecked locally: `npm test` passed 8/8 and
  `npm run check` passed. This verifies local protocol/allowlist behavior, not
  an authenticated production session call.
